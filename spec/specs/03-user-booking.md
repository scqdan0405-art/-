# 03. 利用者向け機能仕様

ルート: `/[locale]/...`。モバイルファースト(375px基準)。ヘッダーに言語切替。

## 画面1: 店舗検索 `/`

- 店舗カードリスト(名称・エリア・営業時間・残容量バッジ)。地図表示はPoCでは静的リンク(Google Maps URL)でよい
- 日付選択(今日〜7日先)。日付変更で残容量を再取得
- 残容量: `availablePoints ≥ 3` で「空きあり(緑)」、1–2で「残りわずか(橙)」、0で「満杯(赤)・選択不可」

## 画面2: プラン選択 `/book/[storeCode]`

- サイズ(S/M/L)ごとに個数を +/- で選択(合計1〜5個)
  - サイズ目安を表示(00と同一・非重複): S=20kg以下 / M=20kg超〜30kg以下 / L=29in以上または30kg超。「実物が異なる場合は店頭でサイズ修正・差額精算あり」の注記を出す
- プラン(3/6/12h)選択 → `POST /quotes` で合計表示。**金額計算はサーバーのみ**(PoCでは insuranceAddonId は送らない)
- 到着時間帯(1時間枠)選択。店舗営業時間内かつ「枠開始+plan_hours」が営業時間内に収まる枠のみ表示(閉店またぎ防止)
- 注意文: 超過10,000 VND/h(最大24h)・基本補償込み(1荷物500万VND上限)・禁止物
- **追加補償オプション(任意)**: 将来対応。PoCではUIを出さない(スキーマのみ先行、常に基本補償)。有効化時に insurance_addons マスタのプランをトグル表示する想定
- **ウォークイン短縮フロー**: `?ref=store_poster&store=<code>` で着地した場合、店舗・利用日(今日)・到着枠(現在時刻)をプリセットし、このプラン選択画面から開始する(07-growth-channels 7.4)

## 画面3: 予約・決済 `/book/[storeCode]/checkout`

入力:
- メール(必須、形式検証+確認用2回入力)
- 電話番号(必須、E.164。国番号セレクタ付き)
- 禁止物チェックボックス「現金・パスポート/身分証・貴重品/宝石/ブランド品・危険物(火災/化学薬物/生物食品系)・生ものを入れていません」(必須)。詳細品目は12.10-C-1・禁止物ワークシート
- 所有物宣言チェックボックス「預ける荷物は自己の所有物です」(必須)
- PC・スマホ・データ/記録媒体は補償対象外である旨の注記(12.10-C-1)
- 補償・免責同意チェックボックス(必須、規約モーダルへのリンク)
- 決済方法(資料明記の6種を選択肢として表示): クレジットカード(Visa/Mastercard)/ Apple Pay / Google Pay / VietQR / MoMo。各方式は `lib/payment/PaymentProvider` のメソッドにマップする
  - PoC実装: 全方式を `MockProvider` で受け(方式ごとに成功/失敗を再現)、UIは6ボタンを出す
  - 本番PSP(確定): **2C2P を採用**。Visa/Mastercard + Apple Pay + Google Pay + MoMo + VietQR を1契約・1連携で提供し、外国人観光客のカード決済を主軸にしつつベトナム現地決済も同一APIでカバーする(将来の方式追加が不要)。代替候補は OnePay。詳細は `specs/10-payment-provider.md`
  - `PaymentProvider` インターフェースに 2C2P 実装(`lib/payment/twoc2p.ts`)を用意。PoCは MockProvider、`PAYMENT_PROVIDER=2c2p` で本番切替。決済方式は 2C2P の Hosted Payment Page で6方式をまとめて提示してよい(自前カードフォームは任意)

処理: `POST /bookings`。二重送信防止(ボタンdisable+idempotency key)。失敗時はエラー種別ごとにメッセージ(容量切れ/決済失敗)。

## 画面4: 予約完了 `/b/[token]`(マイ予約と兼用)

- QRコード表示: ペイロードは `bookingToken` のみ。**OTPを含めない**
- drop-off OTP 6桁を大きく表示(このページ初回とメールのみ。以降の再訪では「メール参照」と表示し、再送ボタンを出す)
- 予約内容サマリ・荷物ごとのステータス・返却期限・超過料金(発生時は赤字表示)
- **pickup OTP 表示(OTP不達対策・06参照)**: 店舗が受取操作でOTP発行済み・有効期間内(10分)・未使用の間だけ、このページに pickup OTP を表示する(「店頭でスタッフに伝えてください」)。メールは予備扱い
- ボタン: 確認メール再送 / **メールアドレス修正(預け入れ前のみ。修正時は新旧両アドレスへ通知)** / キャンセル(預け入れ前のみ。確認ダイアログ→ `refund = total − 20,000 VND` を明示)

## 受け取りタイミングの原則(原資料の明記事項)

- 荷物は **予約時間内(return_due_at まで)ならいつでも受け取り可能**(早い受け取りに制限なし)
- 一度返却した荷物の再預け入れ(出し入れ自由プラン)は将来拡張であり、本PoCでは returned は終端状態とする

## メール(Resend または nodemailer + SMTP。テンプレはロケール別)

1. 予約確認: QRページリンク・drop-off OTP・店舗情報・注意事項
2. pickup OTP: 6桁+10分有効の旨(店舗操作時に送信)
3. no-showキャンセル通知 / 超過発生・24h通知
4. 返却完了1時間後のレビュー依頼(07-growth-channels 7.5)

## 受け入れ基準(E2E)

- [ ] 満杯の店舗では予約ボタンが押せない。同時予約の競合でも容量超過予約が作られない
- [ ] 決済失敗時に booking は payment_failed になり容量が解放される
- [ ] 完了ページのQRを読むと bookingToken だけが得られる(OTPが含まれない)
- [ ] キャンセルは awaiting_dropoff のみ可能。stored 以降は不可(UIにも表示しない)
- [ ] 全文言が i18n キー経由(ハードコード文言なし)。en/vi/ja 完備
