# 04. 店舗向け機能仕様

ルート: `/store`。タブレット/店舗スマホ想定(縦横両対応)。UIは vi をデフォルト、en 切替可。
操作は「預かる」「返す」の2ボタンに集約する(店舗負担最小の原則)。

## ログイン `/store/login`

1. 店舗アカウント(Supabase Auth email+password)でログイン → セッション維持
2. 操作のたびに最初にスタッフ個人コード(4桁)を入力 → 15分間セッションに保持、以降の操作ヘッダに自動付与。15分無操作で再入力
   - アカウント作成・初回パスワード変更強制・スタッフコード発行/失効・パスワード方針は specs/16 参照

## ホーム `/store`

- 大きな2ボタン: 「① 預かる」「③ 返す」+ 保管中一覧
- 保管中一覧: タグ番号・サイズ・返却期限。期限超過は赤ハイライト+超過額表示。15秒ポーリング更新

## 預かるフロー `/store/checkin`

1. QRスキャン(カメラ)または予約番号手入力 → 利用者にOTP(メール記載のdrop-off OTP)を口頭確認して入力
2. `POST /store/verify-dropoff` → 成功で荷物リスト表示
3. 荷物ごとに: タグ番号入力(物理タグを装着)+ 写真撮影(カメラ、必須。撮影なしでは次へ進めない)
   - 写真・保管履歴は運営が管理しシステムが保持する。店舗の役割は記録のみ(責任分界は06参照)。写真は端末に残さない(アップロード後即破棄)
   - **サイズ修正(12.10-B)**: 実物が予約サイズと違う場合、スタッフがサイズを修正できる。差額を画面表示し店頭精算 → `size_adjustment_vnd` に記録、容量ポイントを実サイズで再確保。修正で容量超過するなら受入不可(運用対応)。
   - **禁止物(12.10-C/C-1)**: 現金・パスポート・貴重品・危険物等が見つかったら「受入拒否」ボタン → 予約を `cancelled(prohibited_item)`、`refund = total − cancellation_fee`、`refund_status=pending`、audit記録。
   - **利用拒否(規約)**: 泥酔・暴力/威圧・本人確認拒否・危険物所持・虚偽申告は利用拒否可。事象をaudit記録。
   - **開披(12.10-C-1)**: 煙・異臭・液漏れ・発熱・薬物疑い時は責任者立会いで開封可。開披をaudit記録。緊急時初動(触れない→報告→隔離→消防→警察)・重量物2名作業は運用/研修マニュアル。
4. 全item入力後「保管開始」→ `POST /store/checkin`(**全item同時**。分割預け入れ不可=12.10-A) → 返却期限を大きく表示「HH:mm までに返却」
5. 失敗UX: OTP不一致は残り試行回数を表示。ロック時は「運営に連絡してください」+運営電話番号

## 返すフロー `/store/checkout`

1. QRスキャン/予約番号入力 → 予約と荷物一覧(タグ・写真サムネイル)表示
2. 「受取OTPを送信」ボタン → `POST /store/request-pickup-otp` → 利用者のメールに6桁送信(マスク済み宛先を画面表示)
3. 利用者が受信した6桁を入力 → 返す荷物を選択(部分受け取り可)
   - メール不達時: OTPは利用者の予約ページ(`/b/[token]`)にも表示される(06)。それも不可なら運営へ連絡(手動オーバーライド=本人確認のうえ管理者対応)
4. 超過がある場合: 超過額を表示 →「店頭QRで精算完了」チェックをスタッフが確認(PoCでは店頭決済は運用対応、システムはチェック記録のみ)
5. `POST /store/checkout` → タグ・写真と照合して荷物を引き渡し

## 受け入れ基準

- [ ] スタッフコード未入力ではすべての操作APIが403
- [ ] 写真なしで保管開始できない
- [ ] pickup OTPなしで返却できない(drop-off OTPの流用は不可 = 別テーブル検証)
- [ ] OTP5回失敗で15分ロックされ、audit_logs に記録される
- [ ] 2個口のうち1個だけ返却→残り1個が一覧に残り、bookingはactiveのまま
- [ ] overdueのitemは overtimeSettled なしで返却できない(409)
