# 05. 管理者向け機能仕様

ルート: `/admin`。Supabase Auth + admin ロール(app_metadata.role='admin')。デスクトップ想定。UIは ja/en。

## ダッシュボード `/admin`

- 期間フィルタ(今日/7日/30日/カスタム)
- KPIカード: 総予約数 / 保管中item数 / 総売上VND / 返却完了数 / no-show数
- 店舗別テーブル: 予約数・売上・稼働率(使用ポイント÷容量ポイントの日平均)
- 収益内訳(自動計算): 売上 − 店舗40% − 決済3% − 保険6% − システム5% = 純収益

## 予約管理 `/admin/bookings`

- 検索: 予約番号 / メール / 電話(部分一致)、状態・店舗・期間フィルタ、ページネーション50件
- 詳細ドロワー: 予約全項目 + item一覧(タグ・写真・状態)+ audit_logs タイムライン
- 操作: 手動キャンセル(返金額入力+理由必須。paidのみ可) / OTPロック解除

## 日次レポート `/admin/daily`

- 店舗×日別のマトリクス表(期間フィルタ、デフォルト直近14日)
- 列: 日付 / 店舗 / 預かり件数(その日にstoredになったitem数) / 荷物個数内訳(S/M/L) / 返却完了数 / キャンセル数(no-show / 利用者都合を別掲) / 超過発生数 / 売上VND / 流入チャネル別内訳(粗カテゴリ direct/organic/ota/referral/store/sns。ドリルダウンで channel_code 別=trip/klook/agoda等。チャネルは sales_channels レジストリ由来)
- 行クリックで該当日の予約一覧(予約管理画面に日付+店舗フィルタ付きで遷移)
- CSVダウンロード対応(PoCのKPI検証「1店舗あたり1日5〜10件」の実測に使う)
- 店舗向け `/store` ホームにも自店舗の「本日の預かり数 / 返却数」カウンタを表示する

## 精算 `/admin/settlement`

- 月選択 → 店舗別精算テーブル(総売上・店舗委託料40%・控除・純額)
- CSVダウンロード(`?format=csv`、UTF-8 BOM付き — Excelで開けること)

## 店舗・マスタ管理 `/admin/stores`

- 店舗の有効/無効、容量ポイント、営業時間の編集
- 料金マスタ(price_plans): 新しい valid_from 行を追加する方式(過去行は編集不可 — 予約スナップショットとの整合)
- **料金設定マスタ(fee_settings)**: 超過単価/打ち止め時間/**日額保管料**/キャンセル手数料/no-show手数料/移送日数/補償上限 を画面から編集(effective_from で改定履歴を残す)。
  - **`daily_storage_fee_vnd` は初期 null(未確定・調査中)**。ダッシュボードに「日額保管料が未設定」の警告を出す。設定するまで日額課金は発生しない(0扱い)。
- スタッフ管理: 追加(コード自動生成)・失効・再有効化(削除・再割当はしない)。詳細は specs/16
- 店舗アカウント管理: 作成(初回パスワード発行+初回変更強制)・ban・強制リセット。詳細は specs/16
- **通知テンプレ管理(`/admin/templates`, specs/14)**: 通知キー×ロケールの件名・本文編集、変数一覧表示、サンプル描画プレビュー、有効/無効。変更は次回送信から即反映。

## 受け入れ基準

- [ ] adminロールなしのユーザーは /admin 全ページで404
- [ ] 精算CSVの合計がダッシュボード売上と一致する
- [ ] 料金改定後も既存予約の金額が変わらない(スナップショット検証)
- [ ] 手動キャンセルで capacity_holds が解放される
- [ ] fee_settings を変更すると以後の計算に反映され、既存予約のスナップショットは変わらない
- [ ] daily_storage_fee_vnd が null の間は日額課金が発生せず、未設定警告が出る
