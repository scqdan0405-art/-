# 07. 集客チャネル機能(広告費ゼロ集客の基本 — 原資料の6チャネルに対応)

原資料「お金をかけない集客チャネル」の各項目をシステム要件に落とす。PoCで実装するのは本ファイル全部(軽量)。

## 7.1 SEO公開ページ(Google検索/Maps)

- 店舗ごとの公開ランディングページ `/[locale]/stores/[storeCode]`(予約フローとは別の、検索流入用静的ページ)
- 内容: 店舗名・住所・地図(Google Maps埋め込みリンク)・営業時間・料金表・利用手順(3ステップ図解)・FAQ・予約ボタン
- SEO要件: SSG/ISRで生成、`LocalBusiness` 構造化データ(JSON-LD)、7ロケールのhreflang、OGP、`sitemap.xml`・`robots.txt` 自動生成
- タイトル例: "Luggage Storage near Ben Thanh Market | from 50,000 VND | KONCOCHII"
- Googleビジネスプロフィールからこのページへリンクする運用(システム外だがURL設計はこれを前提に安定させる)

## 7.2 流入元トラッキング(全チャネル共通)

- すべての着地URLで `?ref=<code>` と UTMパラメータを受け付け、セッション保持し、予約作成時に `bookings.channel` / `bookings.referral_code` へ保存
- channel 値: `direct` / `google` / `maps` / `ota_trip` / `ota_klook` / `ota_kkday` / `hotel` / `bus_tour` / `store_poster` / `sns`
- 管理の日次レポート・ダッシュボードにチャネル別内訳を追加(PoC KPI「自然流入比率」の実測)

## 7.3 紹介パートナー(ホテル・宿泊施設・バス/送迎・ツアー会社)

- `partners` テーブルで紹介元を管理(名称・種別・紹介コード)
- パートナーごとに固有QR付き案内POP(A5)を管理画面からPDF生成(`/admin/partners` → 「POP生成」)。QRは `https://<domain>/?ref=<partnerCode>` を指す
- チェックアウト後・乗車前後の荷物ニーズ向け: パートナーコード経由の予約数を管理画面で集計(PoCではキックバック計算はしない — 件数把握のみ)

## 7.4 店頭ポスターQR・ウォークイン(その場で予約)

- コンビニ店頭ポスター/レジ周辺QRからの「今すぐ預ける」フローを明示的にサポート:
  - QRは店舗固定URL `/?ref=store_poster&store=<code>` → 店舗選択済み・利用日=今日・到着枠=現在時刻の枠がプリセットされた短縮フロー(3タップで決済画面へ)
  - 現在時刻の枠が営業時間内なら常に選択可能にする(事前予約専用にしない)
- 店舗別ポスターPDFも管理画面から生成(店舗QR+3ステップ説明+料金表)

## 7.5 SNS・口コミ(レビュー導線)

- 全item返却完了(booking completed)の1時間後に「ご利用ありがとうございました」メールを自動送信
- 内容: 利用店舗のGoogleマップレビューURL+SNSシェアリンク。PoCでは自前レビュー機能は作らない(Googleレビューへ誘導が方針に合致)
- 配信はcronで処理(completed_atから1時間経過・未送信のもの)

## 7.6 問い合わせフォーム

- `/[locale]/contact`: 名前・メール・予約番号(任意)・本文。送信で管理者へメール通知+`inquiries` テーブルに保存
- 管理画面 `/admin/inquiries`: 一覧・状態(open/closed)・対応メモ。スパム対策に簡易レート制限(3件/時/IP)
- 店舗は問い合わせ対応をしない(原資料の役割分担どおり)。店舗のトラブル報告は既存の audit + 管理者通知を使う

## 受け入れ基準

- [ ] 店舗公開ページがJS無効でも内容表示される(SSG)+構造化データがリッチリザルトテストを通る
- [ ] `?ref=` 付き流入から予約するとchannelが正しく記録され、日次レポートにチャネル別で出る
- [ ] ポスターQR→決済画面まで3タップ以内(店舗・日付・時間帯がプリセット)
- [ ] 返却完了1時間後にレビュー依頼メールが1回だけ送られる
